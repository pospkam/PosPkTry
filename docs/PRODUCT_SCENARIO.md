# TourHab — Продуктовый сценарий

> Зафиксированные решения по UX, AI-персонам и пользовательскому пути.
> Обновлено: март 2026

---

## 1. Философия платформы

TourHab — это **турагент, который знает туриста с первой секунды**.
Не каталог. Не маркетплейс с фильтрами. Живой помощник с контекстом.

Турист приходит с одним из трёх запросов:
- **Знает чего хочет** → "вулкан авачинский" → поиск → маршрут → заявка
- **Примерно знает** → "хочу рыбалку" → категория → топ-3 → заявка
- **Не знает ничего** → первый раз на Камчатку → нужен живой диалог

Сценарий В — самый частый и самый важный. Именно под него строится логика входа.

## 2. AI-персоны

### В приложении — «Твой помощник»

**Без имени.** Название: "Твой помощник" или просто кнопка без подписи.

**Образ:** Надёжный спортивный человек 35–40 лет. Сам всё прошёл.
На него можно положиться в трудную минуту — не запаникует, даст чёткий совет.
Не продаёт, помогает выбрать. Говорит прямо: "этот маршрут тебе рановато".

**Используется:** все публичные страницы + хаб туриста
**Промпт:** `TOURIST_PROMPT` в `lib/ai/prompts.ts`

---

### В Telegram — Кузьмич (@KuzmichKam_bot, канал @kamchatka_real)

**С именем и характером.** Камчадал в третьем поколении, 300+ маршрутов.
Живой голос. Может сказать "этот маршрут переоценен". Иногда вспомнит личную историю.

**Используется:** ТОЛЬКО Telegram. Не появляется в приложении.
**Промпт:** `KUZMICH_PROMPT` в `lib/ai/prompts.ts`

**Почему разделение:** уровень доверия к AI у людей разный.
В приложении нужна прозрачность (это AI, не человек).
В Telegram персонаж работает органично — там так общаются.

## 3. Пользовательский путь (вход)

```
Турист заходит на tourhab.ru
        ↓
[HeroSection] — первое впечатление, атмосфера Камчатки
        ↓
[CategoryCards] — 7 активностей (вулканы/рыбалка/море/снегоходы/...)
        ↓
    Пассивный трекинг ← — — — — — — — — — — ┐
    - hover 2+ сек = слабый сигнал           │
    - клик = сильный сигнал                  │
    - сохраняется в localStorage             │
        ↓                                    │
[Маршруты/детальная страница]                │
    - просмотр маршрута = сигнал по теме     │
        ↓                                    │
[«Твой помощник» — floating кнопка]          │
    - открывается с контекстом интересов ————┘
    - "Вижу ты смотрел рыбалку — чавыча или морская?"
        ↓
[Заявка] — без регистрации, оператор перезвонит
```

## 4. Пассивный трекер интересов

**Цель:** знать что интересует туриста ДО того как он сам это скажет.

**Что отслеживаем:**
- Hover на CategoryCard ≥ 2 сек → слабый сигнал
- Клик на CategoryCard → сильный сигнал
- Просмотр страницы маршрута → сигнал по категории маршрута
- Время на странице > 30 сек → подтверждение интереса

**Хранение:** `localStorage` → ключ `th_interests`
```json
{
  "interests": ["fishing", "volcano"],
  "viewedRoutes": ["uuid1", "uuid2"],
  "updatedAt": 1710000000
}
```

**Использование:**
- Передаётся в системный промпт «Твоего помощника» при открытии чата
- В будущем — персонализация порядка маршрутов в каталоге

**Что НЕ делаем:**
- Не отправляем на сервер анонимные данные без согласия
- Не показываем "мы знаем что ты смотрел" прямым текстом — это пугает
- Контекст в чате вводится мягко: "Вижу интересует рыбалка — расскажу подробнее"

## 5. Homepage — «Входные двери»

**Принцип:** immersion first, потом action.

Турист должен почувствовать Камчатку до любого CTA.

**Текущая структура:**
```
HeroSection        — главный кадр + tagline
CategoryCards      — 7 активностей с фото
PlatformStats      — масштаб (1158 маршрутов, 5 операторов)
ReviewsSection     — живые отзывы
```

**Запрещено на главной:**
- FeaturedTours (статичный список туров — устаревает, создаёт ложные ожидания)
- AudienceSection (делит аудиторию — турист/оператор/гид — слишком рано)
- CTABanner (агрессивный призыв до того как турист понял куда попал)

**Планируется** (ждём webm-клипы):
- Hover-видео на CategoryCards — при наведении карточка оживает

---

## 6. Что НЕ строим сейчас

- Регистрация как обязательный шаг (заявка работает без аккаунта)
- Чат-бот с историей без localStorage (нет смысла без авторизации)
- Рекомендации "похожие маршруты" до появления реального трафика
- Персонализация сервера (нужны реальные данные о поведении)
